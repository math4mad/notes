# 图书馆入口建议 · 投递与成功率台账

> 主人 1001 令（2026-10-02）：**没有邮箱的就不管**；**若两馆有回音，再发 1–2 线城市**；
> **做成功率的统计，衡量方法的说服力**。

## 一 · 方法（被投递之物）

把图书馆入口的**「安检」与「入馆」两段解耦** —— **安检前置 · 篮子预存**：

1. 馆外设预存区，备带编号的篮子；
2. 开门前的等候时段，读者将包／电脑放入篮子、登记取对号牌，馆方**提前安检并加一次性封条**；
3. 开馆后凭牌取篮、走「已安检」通道，**免二次安检**；
4. 篮数按早高峰配置；封条破损者重检。

正文见 `proposal.md`。本质＝排队论**前置预处理／缓冲**。

## 二 · 为什么记成功率

投书 ＝ 一次**说服力实验**：一个方法若真有说服力，应能换来**回音、乃至采纳**。
故以**小样本、分线城市**统计——

| 指标 | 定义 |
|---|---|
| **回复率** | 有回音数 ／ 投递数 |
| **正向率** | 明确推进／采纳数 ／ 投递数 |
| **退信率** | 退信数 ／ 投递数 |

它衡量的不是"我们说得对不对"，而是"**这个说法能不能撬动对方**"——正是**说服力**。

## 三 · 扩张律（主人令）

1. 先投 **一线大馆**：广州、上海（各一封）；
2. **若得回音** → 扩至 **1–2 线城市**大馆；
3. 无回音 → 不扩（样本即结论的一部分）。

## 六 · 定期巡检与阈值告警（主人令：定期收，达 5 回复则通知）

- **巡检器** `check_replies.py`：扫邮箱（`agently-cli message +search --from`）→ 回音写回 `outreach.csv` → 计有回音数。
- **定时**：launchd `com.concept-space.lib-proposal`，**每日 09:30** 跑一次（`--notify --threshold 5`）。
- **阈值告警**：回音累计 **≥ 5** → 挂一条 iPhone 提醒（`bin/remind.sh`）＋ 打印哨 `THRESHOLD-REACHED`。
- **日志**：`/tmp/concept-lib-proposal.log` ／ `.err`；plist 副本存本目录。
- 手动：`python3 check_replies.py --notify --threshold 5`

## 七 · 方案二 · 人货分流（传送带）

> 主人 1001 续想：借大润发收银**传送带**——“包上带、**要上几楼提前设定好**；**大厅的拥堵都可以解决**。”

- **人走人道**（无包、快）；**包走传送带**（过安检机、按预设楼层路由），到楼层「取包口」自取。
- 关键仍两件：**安检随带而过**（带穿安检机，人不必停）；**目的地预设**（对号／条码 → 楼层）。
- 现成名物：机场行李分拣 · 大馆的**还书自动分拣传送带** · 医院气动物流。
- 界：**大馆（多层大厅）才值当**；小馆（大岭山）**不必**——篮子预存足矣。
- 同源一句话：**拥堵 ＝ 两条流耦合在同一通道；解法 ＝ 把两条流分开。**

（方案一「篮子预存」解的是**入口安检**；方案二「人货分流」解的是**大厅拥堵**——同一把刀，切的是一处。）

## 八 · 先验因素：接受度不是一个数，是一个先验

主人 1001 观察到：**广州图书馆已有「自动取书系统」**——“领导对我们的这个方案应该认同率高一点。”

这句话可以写成园中的话：**一个新方案的接受度，不是它自身好坏，是它落到什么先验上。**

- 图书馆的**既有技术底座**（自动化程度、有无分拣/取书系统）= **它的先验**；
- 底座越自动化 → 新方案的**先验越高**（“我们已经这么干了”比“从零学起”容易得多）；
- 故可把它当成一个**可统计的协变量**：按"**有／无自动化底座**"分层，各算回复率——**看回应是否真与先验相关**。

台账已添一列 `readiness`（广州＝**高**；上海＝待考）。

（这正是《先验-后验袜对》的人间用法：**同一封信投出去，回音高低，先取决于对方的先验。**）
